## Overview

This project takes you through the full CRISP-DM pipeline on a real-world car sales dataset, from raw data exploration through serialized model artifacts (actual deployment will be saved for the next unit). Over the course of seven checkpoints, you will produce a set of Jupyter notebooks covering EDA, preprocessing and feature engineering, classical machine learning, neural networks, imbalanced classification, and model interpretability. You will maintain a structured GitHub repository that functions as a reproducible training pipeline: every artifact — processed datasets, selected-feature datasets, and trained models — is generated by running the notebooks in order and can be fully recreated by doing so again. By the end of the unit, your repo should be clean enough that a stranger could clone it, install the requirements, run the notebooks sequentially, and reproduce everything from scratch.

### Dataset

The dataset is a modified version of the [US Used Cars Dataset](https://www.kaggle.com/datasets/ananaymital/us-used-cars-dataset) on Kaggle. It contains listings of used cars sold across the United States with features covering vehicle attributes (`make`, `model`, `year`, `body_type`, `transmission_display`, `fuel_type`, `engine_type`, `engine_cylinders`, `engine_displacement`, `wheel_system_display`), performance specs (`horsepower`, `torque`, `city_fuel_economy`, `highway_fuel_economy`), physical dimensions (`height`, `length`, `width`, `wheelbase`, `maximum_seating`, `front_legroom`, `fuel_tank_volume`), condition and history (`mileage`, `owner_count`, `has_accidents`, `frame_damaged`, `salvage`, `theft_title`), listing details (`listed_date`, `major_options`, `daysonmarket`, `seller_rating`, `franchise_dealer`, `franchise_make`, `is_new`), color (`exterior_color`, `interior_color`, `listing_color`), geographic information (`city`, `dealer_zip`, `latitude`, `longitude`), and pricing (`price`, `savings_amount`). The dataset as provided has already been lightly modified from the original — do not assume it is identical to the Kaggle source.

## Checkpoint 2 — Preprocessing
*Notebook: `HW01_CarSales-2_Preprocessing_<LastNameFirstInitial>.ipynb`*

Build a clean, model-ready dataset. **EVERY** decision **MUST** have a markdown explanation. Read in the raw data at the top of this notebook. Do not carry over objects from the EDA notebook.

> **Label leakage warning:** `price` is the basis for your classification target. No engineered feature may use `price` or any column that directly encodes price information. Treat `price` as off-limits for feature engineering — it exists in the dataset solely to define the target in CP3.

Your preprocessing **MUST** address:

- **Dropping**
    - Columns that are genuinely useless, rows that cannot be salvaged — justify each
- **Imputation**
    - Strategy should depend on the column and what makes domain sense
    - There are many places where you can be more clever than simple median/mode/unknown filling
- **Data types**
    - Some columns have mixed data types — normalize these to a single data type
- **Outlier handling**
    - Handle `year`, `price`, and `mileage` at minimum
    - Justify your method and thresholds
    - **MUST NOT** drop more than 50% of rows — confirm this with code
- **Feature engineering**
    - Derive as many informative features as you can from what's available
    - Some columns (e.g., `major_options` and `listed_date`) require careful parsing before they can be used — figure out how
    - **No engineered feature may use `price` or any column that is a direct function of price**
    - After the progress report, all students will implement everyone's engineered features plus any additional ones the instructor specifies
- **Encoding**
    - Label-encode binary columns
    - One-hot encode nominal columns with the reference category dropped
- **Scaling**
    - Standard-scale non-metadata all features **except `price`**, which must remain in its original dollar units
- **Preserving subgroup metadata**
    - Retain the original object-dtype version of every categorical column that gets encoded (e.g., keep original `make` alongside its dummies `make_Toyota`, `make_Honda`, etc.)
    - These columns will be used for the fairness audit in CP7; they must be present in all exported datasets but must be excluded when constructing `X` and `y` for any modeling step
- **Export**
    - Perform a train/test split using `random_state=2049`
    - Save the two splits to your local class data folder as `processed_train.csv` and `processed_test.csv`

You will be graded on the breadth and quality of your **first-pass** feature engineering — the features you come up with before the progress report. Try to be comprehensive on this first pass.
