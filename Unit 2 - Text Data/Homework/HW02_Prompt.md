### Datasets

**MPST — Movie Plot Synopses with Tags**  
[Kaggle: MPST: Movie Plot Synopses with Tags](https://www.kaggle.com/datasets/cryptexcode/mpst-movie-plot-synopses-with-tags)

The Kaggle download contains several files; use **`mpst_full_data.csv`** — the complete dataset of approximately 14,800 movies. Do not use the pre-split `mpst_train.csv` / `mpst_test.csv` / `mpst_val.csv` files; you will perform your own stratified split. Relevant columns: `imdb_id`, `title`, `plot_synopsis`, and `tags` (a comma-separated string of crowd-sourced plot descriptors such as `"murder, flashback, revenge"`).

**Expanding tags into binary columns**  
Expand the `tags` column into one-hot dummy columns using `df['tags'].str.get_dummies(sep=', ')` and drop the original `tags` string column. The resulting dummy block contains approximately 70+ tag columns. These binary tag columns are your modeling targets.

### Focal Tag & Tag Suite

In **CP1** you will choose a **focal tag**: one tag column from the MPST one-hot set that you will analyze in depth throughout the unit. Choose a tag that is interesting to you but that also has a reasonable positive class rate — at minimum, at least 15% positive examples. Justify your choice based on class balance statistics computed in CP1.

You will also define a **tag suite**: the **5 most common tags** in the dataset (by positive count), which will be used for the suite-level models that power the Streamlit app. The tag suite is fixed once and applies to CPs 2 and 3.

## Checkpoint 1 — Text EDA
*Notebook: `HW02_MovieGenre-1_EDA_<LastNameFirstInitial>.ipynb`*

Produce a thorough exploratory analysis that would let someone who has never seen this dataset understand its structure, text characteristics, class balance, and data quality issues. Load `mpst_full_data.csv` at the top of this notebook, expand the `tags` column into binary dummy columns, and **save the result as `mpst_labeled.csv`** — subsequent checkpoints read from this file.

Your analysis **MUST** cover at minimum:

- **Dataset construction**
    - Shape and dtypes of the raw source before and after tag expansion
    - Final shape of the dataset after one-hot encoding the `tags` column
- **Text characteristics**
    - Synopsis length distribution (character count and approximate token count); report mean, median, min, max
    - Are there missing, empty, or unusually short synopses? Flag and count them
    - Are there duplicate synopses (same text for different movies)? Report count
- **Vocabulary**
    - Top 25 most frequent words in the synopsis corpus (after lowercasing and basic punctuation removal, before stop-word removal)
    - Discuss what these high-frequency terms tell you about the corpus
- **Tag / class balance**
    - For **ALL** tag columns, plot and report positive class counts and positive rates
    - Identify which tags are severely underrepresented (< 5% positive rate) and which are dominant (> 40%)
- **Focal tag & suite declaration**
    - Choose your **focal tag** and justify the choice based on positive class rate and personal interest — document this decision in a markdown cell
    - Identify the **5 most common tags** by positive count and declare these as your **tag suite** — these 5 will be used for the multi-tag models in CPs 2 and 3

For **EVERY** data quality issue you find (nulls, malformed synopses, suspect values), document it in a markdown cell and flag it for the preprocessing step in CP2.

## Checkpoint 2 — Vectorization & Modeling
*Notebook: `HW02_MovieGenre-2_Modeling_<LastNameFirstInitial>.ipynb`*

Read in `mpst_labeled.csv`. Build and compare tag classifiers using three different text representations. Use clear markdown section headers to delineate your work.

**Defining the target:** Use the binary column for your **focal tag** as `y`. Drop any rows with a missing synopsis before splitting. Perform a stratified train/test split using `random_state=2049`.

**Focal tag modeling — MUST include:**

- **Three text representations**
    - `CountVectorizer` (bag of words)
    - `TfidfVectorizer`
    - Sentence embeddings (your choice of model — document the model ID and dimensionality)
- **Classifiers**
    - Train **AT LEAST 4** different classifier types for each representation; **ONE MUST be a tree ensemble** (e.g. Random Forest or Gradient Boosting)
    - Use `sklearn.pipeline.Pipeline` for CountVec and TF-IDF models; embeddings are pre-computed, so you can train classifiers on the embedding matrix directly
    - Use `GridSearchCV` with a meaningful parameter grid for each pipeline — document what you searched and why
- **Imbalance handling**
    - Use `SMOTE` (or another oversampling method from `imblearn`) to address class imbalance
    - To avoid resampling leakage, use `imblearn.pipeline.Pipeline` or apply resampling only within each CV fold
- **Evaluation**
    - Classification report and confusion heatmap for **EVERY** model × representation combination
    - Rank all models by macro-F1 in a single summary table
    - Discuss which representation wins and why; discuss which classifier wins and why
    - NOTE: If your accuracy and other metrics are near 100%, you have made a mistake somewhere
- **Export**
    - Save every `best_estimator_` to `models/` following the naming convention above
    - Save every fitted `CountVectorizer` / `TfidfVectorizer` to `models/` — you will need these to transform new text in the app

**Tag suite modeling:**

Using the representation that performed best for your focal tag, train one binary classifier for **EACH** tag in your suite (including your focal tag if it is in the suite). These need not be exhaustively grid-searched — use the best hyperparameters you found above. Save each model and its vectorizer to `models/` with a `_suite` variant suffix (e.g. `HW02_CP2_tfidf_logreg_suite_murder.pkl`).
